= BlitzLLVM

BlitzLLVM is a compiler for BlitzBasic, Blitz3D and BlitzPlus programs built on the LLVM compiler backend. It turns a `.bb` program into one self-contained executable, using LLVM's optimizations and its support for many architectures and platforms. Graphics are drawn through Vulkan 1.3 into an SDL3 window.

== Compatibility

The goal is to run existing programs unchanged:

* Every command of Blitz2D, Blitz3D and BlitzPlus is implemented, including the BlitzPlus windows and gadgets (drawn inside the Vulkan window).
* The language is complete: `Type` with `New`, `Delete`, `First`, `Last`, `Each` and `Handle`, `Dim` arrays, `Data`/`Read`/`Restore`, `Goto`/`Gosub`, `Include` and `Function`.
* The 3D world is covered: meshes (also from B3D, MD2, 3DS and BSP files), surfaces, brushes, textures, sprites, terrains, lights, fog, animation, collisions and picking.
* `blitzcc` keeps the original's behavior of building and running a program when no output is requested.

Where BlitzLLVM behaves differently, or a feature is still missing, it is listed on the https://github.com/Xaymar/BlitzLLVM/wiki/Differences[Differences page] and in the "Differences and known gaps" part of each command's page in the https://github.com/Xaymar/BlitzLLVM/wiki/Command-Index[command reference].

The Differences page is generated, so never edit it by hand. A command that differs gets an `@gap` line in its file in `tools/wiki/text/<Dialect>/<Category>/<Command>.md`. A difference that no single command causes (a renderer detail, a new type, an environment variable) gets a page of its own in `tools/wiki/pages/`, with a line `@difference One sentence summary.` under its heading. Then run `python3 tools/wiki/wiki.py build`, which lists both on the Differences page, and commit the result.

== New in BlitzLLVM

Beyond the originals:

* Optimizing LLVM backend with `-O0` to `-O3`, `-Os` and `-Oz`, `--fast-math`, link time optimization and `--llvm-flag` passthrough.
* Cross-compiling with `--target`, and builds for Windows, Linux and macOS.
* `blitz-format` formats `.bb` source code (indentation, keyword case, spacing, blank lines) from a `.blitz-format` or `blitz-format.json` file or from the command line, with `--check`, `--diff` and `-i`. See https://github.com/Xaymar/BlitzLLVM/wiki/blitz-format[blitz-format].
* Debug builds with source file, line and column information (`-d`, `-g`).
* A borderless window mode (mode 4) for `Graphics` and `Graphics3D`.
* Display and refresh rate enumeration (`CountDisplays`, `CountDisplayModes`, `RefreshRateAt` and related commands).
* Reversed 32-bit float depth buffer, which makes z-fighting much rarer.
* Mip maps (including stored DDS levels), sphere maps and cube maps for textures.
* Image decoders for PNG, JPEG, BMP, TGA, WebP, AVIF and JPEG XL.
* Multiplayer over TCP instead of DirectPlay (games can only play with other BlitzLLVM games).
* Warnings for code that is legal but probably not what was meant (`-W1` to `-W4`), and `blitz-tidy`, which fixes them in your source files (`blitz-tidy -i program.bb`, see https://github.com/Xaymar/BlitzLLVM/wiki/Blitz-Tidy[Blitz-Tidy]).

== Installation

Download a build from the https://github.com/Xaymar/BlitzLLVM/releases[releases] or from the https://github.com/Xaymar/BlitzLLVM/releases/tag/nightly[nightly release] (Windows x64, Linux x64, macOS arm64), extract it and keep `bin/runtime/` next to `blitzcc`. You need `clang` on your `PATH` and a Vulkan 1.3 capable driver. See link:docs/wiki/Installation.md[Installation], or link:docs/wiki/Building.md[Building] to compile BlitzLLVM yourself.

== Usage

[source,sh]
----
blitzcc program.bb                    # builds the program in a temporary directory and runs it
blitzcc -o program program.bb         # builds program.exe (Windows) / program (elsewhere), without running it
blitzcc -d program.bb                 # debug build: -O0, debug information, exact floating point math
blitzcc -O3 --fast-math full program.bb
blitzcc --console -o tool program.bb  # Windows: build a console program instead of a GUI program
blitzcc -S program.bb                 # only write the generated LLVM IR (program.ll)
blitzcc --target aarch64-apple-darwin -o program program.bb
----

Common options (`blitzcc --help` lists all of them):

[cols="1,3"]
|===
| `-o <file>` | Create an executable instead of running the program.
| `-O0` to `-O3`, `-Os`, `-Oz` | Optimization level, `-O3` by default.
| `--fast-math <mode>` | `full`, `safe` (default) or `off`.
| `-d`, `-g` | Debug build, or debug information on any build.
| `--console` | Windows only: build a console program. Programs are built for the GUI subsystem by default.
| `-S`, `--emit-llvm` | Only write the LLVM IR.
| `--target <triple>` | Build for another target.
| `--llvm-flag <flag>`, `--llvm-arg <arg>` | Pass a flag to clang, or an argument to LLVM itself.
| `--cc <path>` | Which clang to use (also `$BLITZLLVM_CC`).
| `-q`, `+q` | Quiet, or very quiet.
| `--args <arg>...` | Arguments for the program that is run.
|===

The compiler emits textual LLVM IR and hands it, with the embedded runtime library, to `clang`. SDL3 and the image decoders are linked statically, and the Vulkan loader is loaded when the program starts, so the result is a single executable. Set `BLITZ_HEADLESS=1` to run a program without a window or GPU.

== Testing

`ctest` compiles and runs (headless) every program in `tests/` and lexes `tests/test.bb`. The function test suite, the audio test, the close prompt test and the AutoSuspend tests run twice: as the compiler builds by default (Release) and with `-d` (Debug, which implies `--profile`).

The function test suite in `tests/suite` has a test for every function that Blitz3D and BlitzPlus provide, taken from the original sources in `extra/`. Tests that look at pixels end in `_pixels` and need a window and a GPU; they are skipped when headless and run for real with `-DBLITZ_TEST_GPU=ON`. `tools/suite_functions.py list` rewrites `tests/suite/functions.txt` from the originals, and `check` (also run by `ctest`) makes sure that every implemented function has a test. `tools/suite_signatures.py` compares the arguments of every function in `builtins.inc` with the original.

== Contributing

Run `tools/install-hooks.sh` once after cloning (in git-bash on Windows, in any shell on Linux and macOS). It installs a pre-commit hook that updates the `AUTOGENERATED COPYRIGHT HEADER` of every file the commit adds or modifies, using the authors and years from the history of the file and the author of the commit. Only staged files are touched, and the header is written to the staged and the working tree copy separately, so partially staged files keep their unstaged hunks. Use `SKIP_COPYRIGHT=1 git commit` or `git commit --no-verify` to skip it, and `tools/install-hooks.sh --uninstall` to remove it.
