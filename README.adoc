== What is BlitzLLVM?
BlitzLLVM is an attempt at a BlitzBasic (Blitz2D, Blitz3D, BlitzPlus) compiler using the LLVM compiler backend to enable support for many architectures and platforms. The LLVM backend enables us to take advantage of optimizations and architecture targets that LLVM already provides for other languages, and may even enable further functionality previously considered impossible.


=== Usage
[source,sh]
----
blitzcc program.bb                    # builds the program in a temporary directory and runs it
blitzcc -o program program.bb         # builds program.exe (Windows) / program (elsewhere), without running it
blitzcc -O3 --llvm-flag -march=native --llvm-flag -flto --llvm-flag -fuse-ld=lld program.bb
blitzcc -S program.bb                 # only write the generated LLVM IR (program.ll)
----
The compiler emits textual LLVM IR and hands it, together with the embedded runtime library, to `clang` (`--cc`, `$BLITZLLVM_CC`), so `clang` needs to be installed. `--llvm-flag <flag>` passes any flag to clang, `--llvm-arg <arg>` passes one to LLVM itself (`-mllvm`), `--target <triple>` cross-compiles. The result is one self-contained executable.

The language is complete: `Type` with `New`, `Delete`, `First`, `Last`, `Each` and `Handle`, `Dim` arrays, `Data`/`Read`/`Restore`, `Goto`/`Gosub`, `Include` and `Function`s. Every command of Blitz2D, Blitz3D and BlitzPlus is there, including the BlitzPlus windows and gadgets, which are drawn inside the Vulkan window. What differs from the originals is listed per command in the link:docs/wiki/Home.md[wiki] (start at link:docs/wiki/Differences.md[Differences]).

Graphics are drawn through Vulkan 1.3 into an SDL3 window. SDL3 and SDL3_image are linked statically, including the decoders for PNG, JPEG, BMP, TGA, WebP, AVIF (dav1d) and JPEG XL (libjxl), whose licenses, and those of BlitzLLVM, SDL3, SDL3_mixer and the Vulkan headers, are installed in `licenses/` (`share/licenses/blitzllvm` in packages), and the Vulkan loader is loaded when the program starts, so programs remain a single executable. Set `BLITZ_HEADLESS=1` to run a program without a window or GPU.

Rendering covers the Blitz3D world: meshes (also from B3D, MD2, 3DS and BSP files), surfaces, brushes and textures (layers, blend modes, frames, transforms, render targets), sprites, terrains, lights (directional, point and spot, lit per vertex like Blitz3D), fog, animation, collisions and picking. The known gaps are in the "Differences and known gaps" part of the page of each command, for example cube maps, bump mapping, movies and the lightmaps of BSP levels.

Tests: `ctest` compiles and runs (headless) every program in `tests/` and lexes `tests/test.bb` (a token-level lexer fixture rather than a program).

The function test suite is in `tests/suite`. It has a test for every function that Blitz3D and BlitzPlus provide, taken from the original sources in `extra/`: one file per part (`math.bb`, `strings.bb`, `blitz3d_meshes.bb` and so on) that stops with an error as soon as something is wrong, and `check.bb` with what they share. Tests that look at pixels end in `_pixels` and need a window and a GPU, they are skipped when headless and run for real with `-DBLITZ_TEST_GPU=ON`. `tools/suite_functions.py list` rewrites `tests/suite/functions.txt` from the originals and `check` (also run by `ctest`) makes sure that every implemented function has a test. `tools/suite_signatures.py` compares the arguments of every function in `builtins.inc` with the original.
